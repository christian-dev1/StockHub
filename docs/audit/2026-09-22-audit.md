# Audit StockHub — 22/09/2026

Audit réalisé sur la pile Docker complète (PostgreSQL 18, backend, Angular via nginx, Next.js), avec :

- **309 rendus automatisés** (Chrome headless / Playwright) : 31 pages × 7 largeurs (320 → 1440 px) × thèmes clair/sombre × FR/EN, pour 5 rôles + visiteur non connecté. Contrôles automatiques : débordement horizontal, clés i18n non traduites, erreurs JavaScript, requêtes HTTP en erreur, cibles tactiles, accessibilité **axe-core** (WCAG 2.0/2.1/2.2 AA).
- **38 tests de sécurité en direct** sur l'API (isolation Alpha / Beta, permissions par rôle, jetons falsifiés).
- **Parcours interactifs** : formulaires vides/erronés, recherche, états vides, rafraîchissement (F5), déconnexion, accès direct après déconnexion, menu mobile, clavier.
- Captures de preuve : `docs/audit/screens/`.

---

## Résumé exécutif

Ce qui existe est **solide et propre** : l'authentification, l'isolation entre entreprises et les permissions résistent à tous les tests. Le design Angular est professionnel, le thème sombre et le bilingue FR/EN sont complets sur toutes les pages existantes. Le backend du catalogue (phase 3) est testé (166 tests).

Mais **StockHub n'est aujourd'hui construit qu'à environ 30 %** du cahier des charges :

- phases 1 et 2 terminées ;
- phase 3 terminée côté backend seulement, **sans aucun écran** ;
- phases 4 à 12 (stock, lots, transferts, achats, inventaires, ventes/caisse, alertes, statistiques, exports, prévisions, E2E) **non commencées**.

L'audit a aussi révélé et fait corriger 3 bugs bloquants la veille : connexion impossible via Angular, traductions absentes, erreur de date au tableau de bord. Il relève 13 anomalies MEDIUM et 6 LOW sur l'existant.

**En l'état, le projet ne peut pas viser 19/20** : la note indicative est de **11/20**. La qualité de ce qui est fait est compatible avec l'objectif ; c'est le volume fonctionnel qui manque.
